# Release v2026.11.4

Released 2026-11-12. Upgrades from: `v2026.11.3`.

Upgrade one release at a time:

```bash
git fetch upstream --tags
git merge v2026.11.4
./platformctl upgrade <env>
```

## Kubernetes

Supported: 1.36. Recommended: 1.36.

## Before you upgrade

Nothing to do beyond `./platformctl upgrade`.

## What you may notice

**vLLM v0.33.0.** Every model restarts once with the new image.

- Medusa and MLP-speculator speculative decoding were removed, and
  `--mamba-cache-mode` no longer has an effect. If you pass vLLM flags through
  `extraArgs`, check them against the vLLM v0.33.0 release notes.
- LoRA on a model without LoRA support now fails at startup instead of later.
- Beam search scores are normalised by generated length, `finish_reason`
  reflects what actually happened, and automatic truncation keeps one token
  for generation.
- New size limits on downloaded media can reject very large image or video
  inputs.

**llm-d router v1.0.0** (models of kind `LLMDEndpoint` and `LLMDDisaggEndpoint`).

- Each endpoint's router restarts once during the upgrade, a short
  interruption for that model.
- When the endpoint picker is unreachable, requests now fall back to the model
  servers instead of failing.
- Each endpoint gets a ClusterRole, a ClusterRoleBinding and a
  `<name>-epp-model-servers` Service.
- The router logs a deprecation warning for its `llm-d.ai/v1alpha1`
  configuration. Nothing to do in this release.

**Argo CD 3.6** (self-managed profile) replaces 3.5.

**Platform fixes.**

- The CRDs of Karpenter and the AWS Load Balancer Controller now follow their
  charts on every upgrade. The first upgrade brings existing clusters' CRDs up
  to date.
- `./platformctl down` no longer stalls when an llm-d model is deployed.
