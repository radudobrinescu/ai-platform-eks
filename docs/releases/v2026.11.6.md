# Release v2026.11.6

Released 2026-11-17. Upgrades from: `v2026.11.5`.

Upgrade one release at a time:

```bash
git fetch upstream --tags
git merge v2026.11.6
./platformctl upgrade <env>
```

## What you may notice

- **Langfuse 4, with fresh trace storage.** Langfuse moves from chart 1.x (end of life, frozen Bitnami images) to chart 2. Earlier traces are gone (see the manual steps); new ones appear right away. ClickHouse now runs as `langfuse-clickhouse` (official image, its own Argo CD app); Valkey and SeaweedFS replace the Bitnami Valkey, ZooKeeper and MinIO. On upgraded clusters a post-sync Job deletes the old 1.x volumes (about 82 GiB of EBS) once Argo CD has removed their StatefulSets.
- **LiteLLM 1.83 -> 1.108 (LTS line).** A large jump; nothing in our use changed (models, keys, teams, budgets, SSO, metrics). LiteLLM now sends traces to Langfuse over OpenTelemetry (`langfuse_otel`). Its database is migrated on start-up.
- **Argo CD's Redis 8.6 -> 8.10.** Only Argo CD's cache; the pod restarts.
- **`platformctl down`** clears Argo CD hook finalizers, so a hook Job still running at teardown no longer leaves the cluster behind.

## Kubernetes

Supported: 1.36, 1.37. Recommended: 1.37.

## Before you upgrade

Manual steps:
- Langfuse moves to chart 2 (Langfuse 4) and starts with empty trace storage: traces, observations, scores and sessions recorded before this release are not carried over. Export any you need from the Langfuse UI before upgrading. Projects, users, API keys, prompts and datasets (kept in Postgres) stay.
- Teams onboarded with --langfuse-secret: their per-team LiteLLM callback is the old 'langfuse' callback, which Langfuse 4 rejects. After the upgrade, add it again as 'langfuse_otel' (LiteLLM POST /team/<team_id>/callback, as in platform/config/kro/team-onboarding.yaml) and remove the old one. Platform-wide tracing needs nothing.
